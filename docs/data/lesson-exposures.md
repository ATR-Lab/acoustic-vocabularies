# Provisional lesson observations and audio linkage

This optional export adds the typed lesson handoff requested by #68 to the data journal from #72. It is an engineering schema, not the missing methodology template or a reviewed study export. It does not qualify headset visibility, physical scanout, acoustic onset, participant admission, or a completed native visit.

The joined teaching sink first appends a closed `lesson` record to the existing `DataJournal`, including its normal hash chain and durable flush. It then writes the existing supplementary lesson trace. Either failure propagates to the content owner; a failed typed writer cannot admit later events. A failure between the two writes can leave a durable typed prefix without its supplementary copy. Reconciliation retains this as incomplete evidence, rather than claiming an atomic transaction across files.

Each typed payload uses `schema_version: lesson-events-provisional-1`. It retains every existing `LessonEvent` field and adds the schedule and package hashes, session clock epoch, lesson type, planned slot onset, and all three request IDs. The visit-owned adapter binds a real `SlotContext` only after the matching durable `Loaded` record. It checks that the original opportunity belongs to a non-held-out teaching item in the installed schedule. The journal identity supplies the session, coded ID, visit, station and build. No answers or display text are added.

The adapter and export verifier reject mismatched identities, changed content hashes, changed request IDs, duplicate or reordered presentation indices, reversed clocks, incompatible display boundaries, and closing an interval in a different data clock epoch. Recovery verifies retained events; it does not replay a lesson, generate an end time, or grant a reset/audio permission. An explicit fresh context remains necessary after a stopped process.

## Optional table

Exports containing typed lesson records add `lesson-exposures.csv` and `lesson-header-contract.json`. Both must be present together. The contract is `lesson-exposures-provisional-1`, with `qualified: false` and `acoustic_authority: false`. The public header oracle is `apparatus/data/lesson-exposures.provisional.csv`.

The existing `trial-log.csv` and `exposure-ledger.csv` headers, row counts, uncertainty fields and consumption rules are unchanged. The export manifest's existing `trial_rows` and `exposure_rows` continue to count only those original tables. A bundle containing the new table remains provisional even if an independently reviewed header contract was supplied for the older tables.

| `row_kind` | Source observations | Relation to the original exposure ledger |
| --- | --- | --- |
| `play` | `play_request` through `play_complete`, if retained | One-to-one lookup by actual `audio_request_id`; never an additional exposure |
| `display` | Definition or feedback `display_start` through matching `display_end`, if retained | No audible status or exposure-consumption claim |
| `retrieval` | `retrieval_opportunity` through `retrieval_result`, if retained | No audible status or exposure-consumption claim |

A normal completed lesson yields three play rows, two display intervals, and one retrieval row. This expected shape is not synthesized when records are absent. A request intent with no later audio scheduling record has `audio_ledger_status: request_missing`; its acoustic and consumption fields stay blank. It is not evidence of silence or a free replay. A linked play copies `audible_status`, `exposure_consumed`, `audio_onset_estimate_mono_ms`, and `onset_uncertainty_ms` exactly from the original exposure ledger after verifying context, PCM and constituent hashes. Simulation callback observations therefore remain uncertain/consumed with blank acoustic onset fields.

`presentation_index` is populated only on play rows. Display/retrieval rows retain the exact three context request IDs, meaning ID, PCM hashes and original opportunity/attempt, so they can be joined without inventing an audio ID for a non-audio event. Feedback intervals and retrieval responses retain the bounded feedback content ID. `start_event_sha256` and `end_event_sha256` identify the actual source records.

All observed times come from the original lesson callback. Planned boundaries are retained separately. Display observations mean that the software visibility call returned; they do not measure a physical screen. Missing ends remain blank with `interval_status: incomplete`. `lesson_status: software_ended` requires an emitted end plus the expected software-event counts, but makes no timing claim. An end emitted before the timeline detects a missing playback completion is retained as `software_ended_incomplete`. `interrupted` and `incomplete` remain explicit. Each typed event adds a durable flush before the existing supplementary write. Its effect on native scheduling/display budgets must be measured; synthetic checks do not qualify that cost. No unknown interval is closed at process exit, export time, nominal duration, or the next lesson.

## Verification and compatibility

`tools/mock_visit/lessons.py` independently reconstructs the optional table from hash-verified raw records and compares every exported cell. It also binds typed events to the pinned actual schedule/package and compares the existing supplementary trace. A missing final supplementary suffix remains incomplete; mismatched records are invalid. Old exports without typed lesson records remain supported under their previous interpretation. Historical files are never rewritten to add this table.

The new EditMode cases drive the real `LessonTimeline`, `DataJournal` and `ExportBundle` with synthetic software clocks and audio events. They cover atomic/message lessons, incomplete display intervals, missing scheduling records, failed durable writes, recovery, duplicate presentations and invalid context/hash bindings. Python tests cover schema/header agreement, reconstructed table tampering, acoustic non-inference and old export compatibility. These are software contract checks; actual completed native lessons and reviewed external headers remain separate acceptance work.

The retained [validation record](lesson-exposures.validation.json) pins the tested source and raw result hashes. All 14 new Unity cases passed. The initial combined run had 250 passes, five mismatched-fixture failures and one Windows symlink-privilege skip; only those five cases were rerun with the matching retained package and all passed without source changes (255 distinct cases passed, one skipped). The initial failure output remains retained. The focused Python suite passed 109 cases. Independent Python reconstruction also matched both real C# exports cell for cell: each contained one original trial row, three original audio rows and six lesson rows, with blank acoustic fields and unchanged uncertain/consumed audio status. No native player, headset or acoustic run was performed for this change.
