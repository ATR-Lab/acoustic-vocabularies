# Logging operator and engineering runbook

1. Choose the authorized topology and private local directory on the actual log-writing device/host. Use a fresh coded session identity and SHA-256 of that build identity artifact. Keep linkage data elsewhere. Never configure a public repository path for real sessions.
2. Bind `SessionDataJournal` before constructing `FixedSlotEngine`; bind fresh audio-request IDs before scheduling, and the durable panel hook before opening responses. Feed trusted actual device/reset/focus/gain events on the same owner thread. Append failure must stop exposure and require investigation; no automatic replay follows an uncertain onset.
3. At visit exit, close the writer, then call `ExportBundle.Create` with a never-used private directory. Record its returned manifest hash. For a crash, retain all bytes and reopen with a fresh clock epoch; inspect the preserved tail, first response and interrupted row before safe-boundary recovery. Never repair raw logs in place.
4. Until actual templates are provisioned use `ExportHeaders.Provisional()` and keep the result unqualified. With owner-reviewed files, run `tools/check_data_headers.py --trial-template <private path> --exposure-template <private path> --trial-sha256 <expected hash> --exposure-sha256 <expected hash> --review-sha256 <review evidence hash>`. Compare names **and order**. Unknown columns require a versioned implementation; do not rename columns to conceal a mismatch.
5. No approved encrypted store exists in this environment. Do not upload logs. Provisioning must supply an approved `IApprovedStoreTransport` and preserve its approval evidence. A test/HTTP-success result is not a sync receipt. Confirm every exact stored object version is separately readable and hash verified; keep the receipt outside the immutable export.
6. Investigate incomplete/corrupt records, uncertain onset, reset/input/focus failures, storage-full and upload mismatch with bounded codes. Corrections belong in the separately signed, dated deviation system; append only its trusted ID/hash reference to this stream.

## Reproducing engineering evidence

Use the installed pinned Unity editor and `tools/build-unity.ps1 -Target Test` / `-Target TestPlayMode`. Provision only the already reviewed synthetic DEMO package and converted G1 paths used by inherited tests; optional missing fixtures are not silently counted as pass. Set `DATA_TEST_ROOT` to an ignored local path. Logging tests exercise actual session engine virtual time, direct audio-event adapters, strict schemas, row counts, first response, torn tails, no-onset/retry/yoked cases, conflicts and separate stored-byte verification. They make no audio-device claim.

The process-kill probe references the freshly Unity-compiled `AcousticVocab.DataLogging`, SessionEngine and StudyAudio DLLs plus the already approved Newtonsoft DLL. Build `tools/data-logging-probe/Probe.csproj` with installed .NET 10 and properties `UnityProject`, `NewtonsoftAssembly`, `ProbeOutput`, `BaseIntermediateOutputPath`, `MSBuildProjectExtensionsPath`, all output under `.local`. It has no NuGet package dependency. Then run `tools/data-logging-probe/run-process-kill.ps1 -ProbeDll <private Probe.dll> -FreshRawDirectory <unused private path>`. The supervisor waits for a flushed synthetic Commit, hashes its readable segment, kills only its owned child, and verifies unchanged bytes and interrupted recovery. This is a real process termination of the actual writer DLL; it is **not** a headset/app power-loss test. All incomplete probe artifacts are retained.

Public `synthetic-visit` files use synthetic identifiers and virtual times. `events.jsonl` is an unchanged copy of one private-formatted segment, renamed for publication. `public-manifest.json` hashes the exact published raw/CSV/header bytes and the original export manifest. It is a public evidence manifest, not a directly reloadable deployment bundle or a protocol qualification.
