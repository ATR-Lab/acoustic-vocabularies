# Provisional data journal and export contract

This implements #72's software boundaries. Protocol trial-log/exposure-ledger templates, an approved encrypted destination, deployment ownership and joined participant runtime are not yet supplied. ADR-007 is not accepted by this work. The public columns are an engineering contract, explicitly `data-csv-provisional-1`; the sample is synthetic. There are no names, contact or payment fields, no scores and no raw correction/delete API.

## Durable record

`DataJournal` owns one private visit directory. `DataIdentity` binds an opaque session GUID, coded ID, visit ID, logical station ID, protocol version and SHA-256 of the build identity artifact (not the 40-character Git revision). `EventContext` keeps original scheduled opportunity, actual attempt, and distinct audio-request GUID separate. A retry retains the original opportunity and gets a different attempt and audio-request ID. A content/audio ID can be reused; it is never a play identity.

Each compact UTF-8 JSON line ends in LF. `sequence` begins at zero. `previous_sha256` links the preceding complete record, initially 64 zeroes. `sha256` covers the exact compact UTF-8/LF record with only its own final hash property omitted. Readback rejects duplicate/unknown keys, noncanonical encodings, invalid identities, sequence gaps, altered bytes and clock regressions. The public structural schema is [data-event.schema.json](../../apparatus/data/data-event.schema.json); C# also validates context equality, producer session semantics, finite values, chain ordering and byte identity.

The append path writes and calls `FileStream.Flush(true)` before returning. Only that success adds an acknowledged record. Write/validation failures latch the journal unavailable; the caller must abort before continued exposure. One owning thread performs all appends. Audio thread callbacks never write files: `AudioPlayer` publishes bounded observations on the main thread. Disk latency on the device is not qualified by these tests.

Writer `host_mono_ms` is milliseconds in its explicit `clock_epoch`. On reopen the host supplies a fresh epoch. Session-engine payload timestamps have their own explicitly tagged epoch and independent monotonic check. Audio host observations are converted from seconds to milliseconds; DSP times remain explicitly suffixed `_dsp_s`. Simulation time is not a timing origin. No cross-epoch elapsed duration is inferred.

Every reopen creates a new numbered `events-NNNN.local.jsonl` segment. Earlier files are never truncated, renamed, deleted or updated. A final unterminated tail is preserved byte-for-byte and bound by a recovery record in the next segment: original segment name, tail offset, tail hash and whole-segment hash. Interrupted recovery can preserve multiple tails. A malformed **complete** line fails closed. Limits are 64 KiB per line, 32 MiB per segment, 1,000 segments and 512 MiB verified raw bytes. Exceeding a bound latches failure; there is no silent rotation or data dropping.

## Adapters and meanings

- `SessionDataJournal : ISessionJournal` uses the shared strict `SessionRecordCodec`; the session engine needs no second recovery journal. Cue intent is durable and uncertain/consumed before an audio request. A scheduled play credit alone does not invent an audio-request row.
- `AudioDataAdapter` requires a prebound `AudioRequestContext` before `AudioPlayer.Schedule`. Its simple opaque `AudioId` handle is distinct from private package paths. Supply the WAV-file hash separately; the audio subsystem's PCM hash is retained as PCM and never relabeled as the waveform file hash.
- `PanelDataAdapter` logs process events through `ProcessRecorded`, emitted after the panel's own durable write. Subscriber failure aborts and locks the panel before Commit confirmation. Its response observation is recorded separately. First response is retained; contradictory later response yields a bounded fault. Selected labels and committed response remain separate.
- `DataObservations` records opportunity metadata, headset/input/focus/reset state, pause, frame freeze, controller exceptions, comfortable gain old/new values and Study B candidate/yoked decisions. Explicit per-play context is required to attribute pause to one exposure. Missing focus is blank; it is not a pass. Gain values are relative controls, not acoustic level measurements.
- `deviation_reference` contains only the ID and hash of an external signed deviation log. It neither edits raw records nor supplies an unreviewed signature/deviation UI.

The trial table has one row per actual attempt; retry rows remain linked by `retry_of`. A merely listed future opportunity does not create a completed attempt. A missed/empty visit has zero attempt/exposure rows. Every actual `audio_request` produces one exposure row, including rejected candidates and yoked plays. Requests without an onset observation remain `uncertain` and consumed. Callback coverage can yield `callback_complete`/`estimated`; neither a successful function return nor a DSP callback is acoustic confirmation. Explicit separately trusted evidence must bind the request. Conflicting no-onset/audible/uncertain evidence remains consumed; earlier confirmed audible cannot later be erased. An interrupted attempt retains its first durable response and is flagged `DATA_INTERRUPTED_ATTEMPT`.

Trial-level waveform/onset fields summarize the first actual request only; `audio_request_ids` links every request and the exposure ledger carries each play. No unused scheduled audio credit is counted as a presentation. A joined host must supply actual device/route/boundary observations; this library does not invent them.

## Immutable exit export and sync

`ExportBundle.Create` verifies closed raw segments, derives both CSVs, and creates a fresh directory. It copies unchanged raw segments, verifies the copies again, and writes RFC 4180 CSVs, header contract and SHA-256 manifest. All writes are create-new and flushed. Failed partial exports remain for investigation and their directory is never reused. Reopening an export requires the manifest hash supplied out of band. The manifest binds raw, both derived files and header contract; the returned manifest hash binds the manifest itself. A sync receipt must be outside the export directory.

[trial-log.provisional.csv](../../apparatus/data/trial-log.provisional.csv) and [exposure-ledger.provisional.csv](../../apparatus/data/exposure-ledger.provisional.csv) define current supported columns. CI checks their exact order against C# and synthetic output. `ExportHeaders.FromReviewedTemplates`/`tools/check_data_headers.py` require actual template bytes, their independently expected SHA-256 values and a review-evidence hash. They preserve reviewed column order and reject unsupported/missing/duplicate columns. A protocol requiring different fields needs a versioned adapter. The owner must provide trustworthy expected hashes; this API does not grant template approval. No actual template qualification is claimed here. Unacknowledged torn tails also prevent export qualification.

`IApprovedStoreTransport` is an injected boundary only. No store, credentials or upload service is provisioned. It must implement an approved encrypted store, create-new immutable versions, bounded I/O, and exact-version `OpenReadAsync`. `VerifiedUpload` computes SHA-256 over a **separately read stored stream**, checks size/hash for every raw/derived/manifest object, rechecks local bytes, then creates a durable receipt. HTTP success, ETag and echoing the requested hash cannot mark synced. Mismatch/cancellation leaves no success receipt and does not delete partial remote artifacts. Tests use an explicitly synthetic in-memory store; no actual logs were uploaded.

Console exposure is `DataJournal.Health` only: writable/failed/closed, durable count/last sequence, bounded fault. `UploadVerification` exposes verified count and manifest hash after readback. The console must never serialize `Records` or raw payloads.

## Remaining qualification

Exact protocol templates and signed-deviation linkage owner; approved encrypted store/transport; joined session/audio/panel/device host; real device crash and power-loss behavior; storage latency/capacity, headset execution and mock visits all remain qualification work. The assembly is compiled into the foundation build as a library; a foundation build does not constitute joined participant-runtime wiring.
