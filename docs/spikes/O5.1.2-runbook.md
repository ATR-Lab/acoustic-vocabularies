# O5.1.2 operator runbook

This runbook produces architecture-spike evidence only. Obtain approval before
installing missing software. The observed host and cached image are Ubuntu 24.04;
the protocol pin is 22.04. Resolve that gap or explicitly label runs nonbaseline.
No physical robot network access is needed.

   `RESULTS_ROOT` and `SPIKE_IMAGE` from ignored station configuration.

## Headless run

The source repositories must be clean at the exact pins. Bind their roots read-only.
Mount writable shader caches that were prepared in the approved image if needed.
No simulation process may use `--network host` or a bridged external interface.

```bash
mkdir -p "$RESULTS_ROOT"
docker run --rm --network none --gpus 'device=0' \
  -e ACCEPT_EULA=Y -e PRIVACY_CONSENT=N -e OMNI_KIT_ALLOW_ROOT=1 \
  -e GIT_CONFIG_COUNT=2 -e GIT_CONFIG_KEY_0=safe.directory -e GIT_CONFIG_VALUE_0=/unitree \
  -e GIT_CONFIG_KEY_1=safe.directory -e GIT_CONFIG_VALUE_1=/lab \
  -v "$SPIKE_REPO:/work:ro" -v "$UNITREE_ROOT:/unitree:ro" \
  -v "$ISAAC_LAB_ROOT:/lab:ro" -v "$ASSET_CACHE:/assets:ro" \
  -v "$RESULTS_ROOT:/results" --entrypoint /bin/bash "$SPIKE_IMAGE" \
  -c '/isaac-sim/python.sh /work/spikes/O5.1.2/run_probe.py --unitree-root /unitree --isaac-lab-root /lab --asset-root /assets --output /results/headless-1 --headless --seconds 600'
```

Use a fresh output directory for every run. A 30-second preliminary run can expose
setup failures but does not satisfy the 600-second criterion. `--preflight-only`
checks source pins, asset presence and the network namespace without launching Isaac.
The existing GPU workload must remain untouched; record its baseline before each run.

Expected outputs: `run.json`, `completion.json` with `completed: true`, 43 rows in
`joint_inventory.csv`, `asset_hashes.csv`, `resources.csv`, `steps.csv`, and
`summary.json`. `run.json` must report fixed base and 29/7/7 joint counts. On failure,
retain the local console log and `failure.json`; do not publish it without redaction.

separate copies of the one-environment command concurrently, with distinct output
directories. Both remain `--network none`. If either cannot initialize or causes
resource pressure, stop only the spike containers and mark two instances infeasible,
with evidence. Do not terminate unrelated GPU processes. Two separate processes and

## Offscreen image and transform checks

For a headless render with an RGB camera, append `--capture`. This records render
timings and saves `robot.png`; it is explicitly labelled offscreen and does not
stand in for the visible viewport run. Append `--pose-evidence` to export measured
joint vectors and link world poses after the timed segment. It includes a neutral
pose, each joint at 25% and 75% of its range, and five deterministic engineering
spread poses. Compare Unity against **measured** joint positions, not the commands.
All body quaternions are `wxyz`, positions are metres in USD world coordinates;
root poses permit a base-relative comparison. Pose export is outside timing samples.

For a separate close hand fixture, use `--capture --hand-visuals` and omit
`--pose-evidence`. It exports three measured poses, retaining default body targets
while flexing fingers through explicit engineering limits, and captures both hands
with a close camera. This leaves the 92-pose comparison suite unchanged. Compare
`poses.json` and the three `pose-hands_*.png` files; do not infer successful grasping
or contact safety from these images. The commanded and actual joint vectors are
both retained.

Kit may release its Python framework on shutdown, so summaries and images are
flushed first. The harness then requests the supported immediate cleanup mode in
this isolated process. A stalled shutdown must be recorded separately from a
completed timed segment; only the spike container may be stopped.
