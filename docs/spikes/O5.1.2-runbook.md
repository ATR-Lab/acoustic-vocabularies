# O5.1.2 operator runbook

This runbook produces architecture-spike evidence only. Obtain approval before
installing missing software. The observed host and cached image are Ubuntu 24.04;
the protocol pin is 22.04. Resolve that gap or explicitly label runs nonbaseline.
No physical robot network access is needed.

## Preparation

1. Approve an isolated image containing Isaac Sim 5.1 and Isaac Lab commit
   `80094be3245aa5c8376a7464d29cb4412ea518f5`. Pin the resulting image digest.
   Follow the linked upstream instructions in the report; the generic unpinned
   `main` install is insufficient. No installation was performed this session.
2. Clone Unitree at `e30c25b1dffdf92ada1d6c8c1fe9a47bdde0fecc` into a local
   dependency cache. The direct configuration probe does not require starting
   Unitree DDS or its teleoperation dependencies.
3. Set shell variables `SPIKE_REPO`, `UNITREE_ROOT`, `ISAAC_LAB_ROOT`, `ASSET_CACHE`,
   `RESULTS_ROOT` and `SPIKE_IMAGE` from ignored station configuration.
   `SPIKE_IMAGE` must be the approved complete image, not the bare cached image.
   Do not paste hostnames, serials or absolute station paths into the public report.
4. Download assets without installing software:

```bash
python3 "$SPIKE_REPO/spikes/O5.1.2/fetch_assets.py" "$ASSET_CACHE"
```

Expected: `Pinned archive verified and extracted`. Inspect license/NOTICE files
inside the extracted bundle. `ASSET_CACHE/assets/robots/...` must contain the
pinned robot. Do not rename arbitrary similarly named assets to satisfy the check.
Network is used only for this asset fetch, before simulation containment begins.

## Headless run

The source repositories must be clean at the exact pins. Bind their roots read-only.
Mount writable shader caches that were prepared in the approved image if needed.
No simulation process may use `--network host` or a bridged external interface.

```bash
mkdir -p "$RESULTS_ROOT"
docker run --rm --network none --gpus 'device=0' \
  -v "$SPIKE_REPO:/work:ro" -v "$UNITREE_ROOT:/unitree:ro" \
  -v "$ISAAC_LAB_ROOT:/lab:ro" -v "$ASSET_CACHE:/assets:ro" \
  -v "$RESULTS_ROOT:/results" --entrypoint /bin/bash "$SPIKE_IMAGE" \
  -c '/lab/isaaclab.sh -p /work/spikes/O5.1.2/run_probe.py --unitree-root /unitree --isaac-lab-root /lab --asset-root /assets --output /results/headless-1 --headless --seconds 600'
```

Use a fresh output directory for every run. A 30-second preliminary run can expose
setup failures but does not satisfy the 600-second criterion. `--preflight-only`
checks source pins, asset presence and the network namespace without launching Isaac.
The existing GPU workload must remain untouched; record its baseline before each run.

Expected outputs: `run.json`, `completion.json` with `completed: true`, 43 rows in
`joint_inventory.csv`, `asset_hashes.csv`, `resources.csv`, `steps.csv`, and
`summary.json`. `run.json` must report fixed base and 29/7/7 joint counts. On failure,
retain the local console log and `failure.json`; do not publish it without redaction.

## Viewport and capacity runs

Repeat for 600 seconds without `--headless`, in the approved desktop session using
its existing display permissions. Pass `DISPLAY` and its existing X socket and
authorization only as necessary; do not broaden access with `xhost +` or change
network settings. Capture `robot.png`; inspect both hands and the fixed base.
An unavailable authorized display is an operator blocker, not a successful viewport run.

Repeat headless with `--num-envs 2` into a new result directory. Then launch two
separate copies of the one-environment command concurrently, with distinct output
directories. Both remain `--network none`. If either cannot initialize or causes
resource pressure, stop only the spike containers and mark two instances infeasible,
with evidence. Do not terminate unrelated GPU processes. Two separate processes and
two environments in one process are distinct results.
