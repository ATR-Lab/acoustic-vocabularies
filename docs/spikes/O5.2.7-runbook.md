## Preconditions that block an actual run

Do not start until each item is resolved and recorded in the private run record:

1. Approval for the exact station set, headset or substitute client per station, power and cooling for eight hours, and each named Isaac process and physical Wi-Fi/uplink fault. Phase 2 development authorization does not cover these.
2. #57: a reviewed supervised launcher and a per-station private gateway that stays up for the whole run. `isaac/e2e/relay.py` is bounded to 3,600 seconds and must not be used. Restarting a relay mid-run is an uplink fault, not continuity.
3. #62 joined host: the feed consumer exists only in the explicitly compiled SimulationTest player ([collection.md](../tests/soak/collection.md#unity-input-feed-consumption)). Decide and record whether that player is acceptable as the station client. An ordinary player refuses `-soakInputs`. Without the feed binding the normalizer has no command or data facts and the result is `NO_GO`.
4. Each station's `CommandDispatcher` `cache_size` exceeds the `commands` count printed by `driver validate` (about 2,800 for the default eight-hour schedule; the default of 1,024 would fault admission).
5. Qualified #56 motion content. Without it, run with `--allow-missing-demo-content`. That records `DEMO_NOT_IMPLEMENTED` per teaching demo and cannot show teaching motion.
6. Note that the 2026-10-05 publisher timing screen still fails. The soak does not waive it.

## Topology and durations

- **Remote Linux Isaac host:** one isolated source per station (`--network none`, mode 0600 private Unix socket), its `DurableCommandLog`, publisher log, `StepTrace` and host sampler. Each writes to a fresh private directory.
- **Station Unity host:** the Unity application with `SoakCaptureHost`, its data journal, the collector and that station's driver. The driver connects to the same station-gateway loopback port that the Unity control client uses (`ws://127.0.0.1:PORT/commands`). The capture directory and input feed stay local to this host.
- **Durations:** schedule and collector window 28,800 s. Unity monitor plan 29,400 s, which leaves startup margin and time to stage remote logs before the Unity terminal. Host sampler 29,400 s.

Keep every path, host name, PID, seed and identifier in ignored private storage (`PRIVATE` below). Commands run from the repository root with the approved Python environment.

## Procedure

### A. Prepare (no station traffic)

1. Validate the fleet manifest on the remote host: `python -m isaac.stations --manifest PRIVATE/fleet.json`.
2. For each station on its Unity host, generate and validate the schedule. Record the seed, the hash and the printed counts:

   ```text
   python -m isaac.soak.driver schedule --station-id station-01 --seed SEED --seconds 28800 --fault-types isaac_crash,wifi_drop,uplink_disconnect --output PRIVATE/station-01/schedule.json
   python -m isaac.soak.driver validate PRIVATE/station-01/schedule.json --sha256 SCHEDULE_SHA256
   ```

3. Write the Unity monitor plan in the [collection.md shape](../tests/soak/collection.md#unity-binding) with `schedule_sha256` = SCHEDULE_SHA256 and `seconds: 29400`, then record its raw SHA-256. Write the collector plan with `seconds: 28800`. Its `source_logs` name local staging files, for example `staging/publisher.native.jsonl`, `staging/command-events.jsonl` and `staging/resources.csv`.
4. `python -m isaac.soak.collect PRIVATE/collector.json --sha256 COLLECTOR_SHA256 --validate-only`.

### B. Start the remote sources

5. Start each station source with the reviewed #57 launcher. Use the configured `cache_size`, a fresh command-log path, the publisher and one `StepTrace.measure()` per simulator step. Record each source PID and the image, scene and snapshot hashes.
6. After the first complete step aggregate, start one sampler per source:

   ```text
   python -m isaac.soak.host --pid SOURCE_PID --gpu-index GPU --steps PRIVATE/station-01/step-trace.jsonl --seconds 29400 --output PRIVATE/station-01/host --source-kind isaac_runtime
   ```

7. From the station host, read the private `/health` endpoint through the gateway (`Invoke-RestMethod http://127.0.0.1:PORT/health`) and record its `control_session_id`.

### C. Start each station host

8. Start the SimulationTest player with its joined and simulation configuration plus `-soakPlan PLAN -soakPlanSha256 PLAN_SHA256 -soakOutput PRIVATE/station-01/capture -soakSchedule PRIVATE/station-01/schedule.json -soakInputs PRIVATE/station-01/driver/unity-inputs.jsonl`. Confirm `JOIN_SOAK_FEED_ONLY` and `SOAK_FEED_BOUND` in the player log. The joined engine and its control client do not start in this mode.
9. Start the collector: `python -m isaac.soak.collect PRIVATE/collector.json --sha256 COLLECTOR_SHA256 --output PRIVATE/collection --startup-timeout 120`.
10. After the collector's start probe is acknowledged, start the driver. Add the last two flags only if all three faults are approved for that station:

    ```text
    python -m isaac.soak.driver run --schedule PRIVATE/station-01/schedule.json --sha256 SCHEDULE_SHA256 --control-session-id SESSION --endpoint ws://127.0.0.1:PORT/commands --output PRIVATE/station-01/driver --authorize-fault-injection --fault-hook operator-file
    ```

    Without fault authorization the slots are logged as not injected and the analyzer reports `missing_fault_type`.

### D. During the eight hours

11. When `PRIVATE/station-01/driver/operator/fault-request-<ID>.json` appears, perform only that approved fault on that station:
    - `isaac_crash`: kill only that station's named source process. Restart it with the reviewed launcher, a fresh command-log path and a new control session. The host sampler is bound to one PID, so it stops. Start a fresh sampler for the new PID in a new directory.
    - `wifi_drop`: disable the station client's Wi-Fi for the approved duration, then restore it.
    - `uplink_disconnect`: unplug the station's approved uplink for the approved duration, then reconnect it.

    Then write `fault-done-<ID>.json` with `{"version":1,"fault_id":"<ID>","fault_type":"<type>","performed":true}`. Record the actual times and console or health captures.
12. Confirm that Unity is paused and logged the fault with its last committed record, and that `/health` answers again. Then write `recovery-<ID>.json` with `{"version":1,"fault_id":"<ID>","control_session_id":"<current session>","operator_initiated":true}`. The driver sends one recovery reset. Resume exposure in Unity only after Unity has received that reset's `reset_ok:true` acknowledgement: write `PRIVATE/station-01/capture/operator-resume-<ID>.json` with `{"version":1,"fault_id":"<ID>","recovery_reset_request_id":"<fault_recovered reset_request_id>","operator_initiated":true}`. Then confirm `SOAK_FEED_OPERATOR SOAK_RESUMED` in the player log. The driver never resumes exposure.
13. If the driver exits early, preserve its output. Restart only after review, with `--resume` on the same output directory. Resume skips to the next block, never replays an unanswered request, and refuses a torn journal or an unrecovered fault.

### E. End and retain

14. The driver writes `driver_end` at about 28,800 s and the collector sends its end probes. Before the Unity terminal at 29,400 s, run `sha256sum` on the remote command, publisher and host files and copy them to the collector's staging paths with `scp`. Compare `Get-FileHash -Algorithm SHA256` locally. The collector retains these snapshots and marks them `terminal_verified:false`.
15. After the Unity terminal and the collector exit, stop the sources with the reviewed launcher. Make final copies of every command log (one per service restart), publisher log, step trace, sampler output and the Unity data journal, and verify each hash. Retain battery and thermal logs for headsets.

### F. Normalize and analyze (offline)

16. For each station:

    ```text
    python -m isaac.soak.normalize --plan PRIVATE/collection/station-01/station-plan.json --plan-sha256 PLAN_SHA256 --native PRIVATE/collection/station-01/soak-native.jsonl --schedule PRIVATE/station-01/schedule.json --command-log PRIVATE/station-01/final/command-0.jsonl --driver-journal PRIVATE/station-01/driver/driver-journal.jsonl --unity-inputs PRIVATE/station-01/driver/unity-inputs.jsonl --data-journal PRIVATE/station-01/final/data.jsonl --output PRIVATE/station-01/normalized
    ```

    Repeat `--command-log` for each restart segment. A refusal is a defect to investigate; do not edit inputs to pass it.
17. Copy the referenced files into one run directory and populate its `manifest.json` from `apparatus/soak/manifest.example.json`:
    - `coordinator_clock_id`: from `collection-summary.json`.
    - Per station, `coordinator_start_s` = start-probe `received_ns`/1e9 and `coordinator_end_s` = end-probe `sent_ns`/1e9.
    - `source_logs`: unity, publisher, command and host, each with its hash.
    - `events`: the normalized `events.jsonl`.
    - `resources`: the sampler's `resources.csv`.
    - The scene, snapshot and detector hashes, and the client kind with any justification.

    After an `isaac_crash`, the analyzer still takes one resource CSV per station. Any join of sampler segments is a reviewed manual step that keeps the restart gap. A gap over 60 s fails resource coverage.
18. Run `python -m isaac.soak.analyze PRIVATE/run/manifest.json --output PRIVATE/run/analysis.json`. It needs a fresh output path. Exit 1 with `NO_GO` is expected for missing, short, synthetic, altered or failed evidence. Exit 0 means only `CANDIDATE_GO` for the declared records, and `g2_signed` stays false.
19. Review the native logs, the normalization mapping, the fault timeline and the resource assumptions. Complete `docs/tests/soak/report-template.md` with sanitized numbers and artifact hashes only. Any failed criterion recommends no-go for live Isaac. The recorded-trajectory/snapshot fallback needs its own validated artifacts and an apparatus amendment.

None of these tools starts or stops stations, kills processes, changes networks or power, replays cues, switches the production state source, or signs G2.
