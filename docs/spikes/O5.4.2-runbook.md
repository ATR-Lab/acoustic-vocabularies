# O5.4.2 response panel: headset check runbook

Part of #65. This covers the checklist item "Check the seated layout on a
headset". It also gives the on-device evidence for the acceptance criteria that
EditMode tests alone cannot establish. Record results in
`apparatus/spikes/O5.4.2/results-template.md`.

**Status: needs operator run.** No headset was connected when this was written.
Nothing in this runbook has been run. Fill in only values you measured or
observed. Leave everything else `Pending`.

## What is already covered without a headset

The panel's EditMode tests and `docs/response-panel/validation.json` cover these
in software:

- the exhaustive 32-tuple legality check
- family-change clearing
- first-response lock
- the exact-boundary timeout
- the distinct `DONT_KNOW` and `TIMEOUT` codes
- journal event order

This run checks on the physical apparatus:

- the same behaviour, with tracked input on the selected method
- the seated panel pose, occlusion of the workcell and reach
- label fit at the configured angle
- accidental presses and input-loss behaviour

Legibility thresholds and the input method choice belong to #49 / ADR-004. This
run records what was configured; it does not select them.

## Before the run

1. Use the pinned editor from `unity/README.md` and the reviewed converted G1
   description used by #61.
2. Build the panel scene. Use a fresh build ID, and use `-Target Windows`
   instead for a Link station:

   ```powershell
   ./tools/build-unity.ps1 -Unity $Unity -Scene ResponsePanel -G1Description $G1Description `
     -Target Android -ProtocolVersion engineering-pending-review -BuildId panel-quest-<nnn> `
     -TemporaryDirectory $PrivateTemporaryDirectory -GradleCache $PrivateGradleCache
   ```

   Expected: exit 0, and `unity/Builds/panel-quest-<nnn>/Android/*.build.json`
   with `development_build: false` and zero errors.
3. Prepare two private configs. Both live outside the repository.
   - The station config: a reviewed copy of
     `apparatus/examples/station.example.json`.
   - The panel config: a copy of
     `apparatus/response-panel/response-panel.example.json`, with
     `configuration_status` set to `provisioned_engineering` and the build's
     `protocol_version`.
   - Its `input_method` must match the station config's (`controller_ray` ↔
     `controllers`, `hand_poke` ↔ `hands`).
   - Record the SHA-256 of both files.
4. Deploy to the named headset with the #59 script. This verifies the APK hash,
   installs the APK, provisions the station config and writes a deploy record:

   ```powershell
   ./tools/deploy-quest.ps1 -Adb $Adb -Serial $DeviceSerial -Python $Python -Apk $Apk `
     -StationConfig $PrivateStationConfig -Record .local/deploy/panel-quest-<nnn>.local.json
   & $Adb -s $DeviceSerial push $PrivatePanelConfig `
     "/sdcard/Android/data/org.acousticvocab.experiment/files/response-panel.local.json"
   ```

   - Keep the device identifier only in the private deploy record. Do not
     write it into the results file.
5. Sit at the station's calibrated seat with the headset on. Do not move the
   chair between runs.

## Runs

Each launch opens **one** request in the configured `engineering_mode`, then
stops. Change `engineering_mode` and `engineering_role` in the private panel
config, push it again, and relaunch for the next run. No study audio is played,
and the start timestamp is an engineering time, not a measured onset.

| Run | `engineering_mode` | What to do | Expected on the headset | Expected in the panel journal |
|---|---|---|---|---|
| R1 | `practice` (60 s) | Look at the panel without touching it, then over the workcell. Note what the panel covers. | Nothing preselected or highlighted. No action row until a target is chosen. | `panel_open`, then no selection events |
| R2 | `full_message` | Select tray B. Read the four K actions. Select ADD_ONE. Switch to container F. Commit should go disabled; read the four Q actions. Select SCAN, then Commit. | The ADD_ONE selection clears on the family change. Commit is enabled only with a legal tuple. The panel locks after Commit. | `select_target`, `select_action`, `action_cleared_family_change`, `commit_disabled` (if pressed), `commit`; then `post_lock_input` for any later press |
| R3 | `full_message` | Select a target and action and do **not** commit. Wait past 12 s, then press Commit. | The panel locks at the deadline. | `deadline_lock`, then `timeout` with the last selection kept; `post_lock_input` for the late press |
| R4 | `full_message` | Press Don't know. | The panel locks. | `dont_know`, with a `response_code` different from R3's `TIMEOUT` |
| R5 | `atomic_probe`, role `action` and role `referent` | Read all eight labels for each role. Commit one. | Only the role's eight options, Commit and Don't know are shown. | `commit` within 7 s of open |
| R6 | `full_message` | With the panel open: for the controller method, turn the controller off or cover it; for the hand method, drop the hand out of view. Then restore it. | The panel hides and latches a fault. Restoring input does **not** reopen it. | a fault record; no new `panel_open` |
| R7 | `practice` (60 s) | Rest both hands in the lap, then reach for the workcell view and back, without aiming at the panel. | No selection. | Count any `select_*` or `commit` as an accidental press |
| R8 | every mode in R1–R5 | Reach every button from the seated pose with the configured hand. | Every button can be reached without leaning or standing. | n/a; record by observation |

## Collect and check

1. Pull the logs into a private folder:

   ```powershell
   & $Adb -s $DeviceSerial pull "/sdcard/Android/data/org.acousticvocab.experiment/files/operator-logs" $PrivateLogDirectory
   ```

2. Check the headers.
   - Each `panel-*.jsonl` starts with schema `response-panel-engineering-v1`,
     the station ID, and the same build identity as the deploy record.
   - The `foundation-*.jsonl` from the same launch has `configuration_validated`
     and `observer_reference_restored` before the panel opened.
3. For R3, compute these from the journal's own monotonic timestamps:
   - deadline lock time minus open time (expected 12,000 ms, not earlier)
   - the late press time, which must be after the deadline
4. Keep the raw logs, any headset captures and the private configs in
   restricted storage.
   - Export only the sanitized results table to the repository, with no
     device identifiers, names or paths.
   - Captures must show no people.

## Pass and fail

- **Fail** if any of these happens:
  - an R2–R5 journal sequence differs from the table
  - any button is unreachable from the seat
  - any label overflows its button (the app raises a fault, never shrinks)
  - R6 reopens without a new explicit request
  - R7 records any accidental press
- **Workcell occlusion** is recorded as an observation for review with #61 and
  #49. It has no automatic threshold here.
- A failed run is kept. Fix the problem and rerun with a fresh build ID.

The issue's acceptance criteria stay with the human reviewer. This run supplies
evidence; it does not sign off.
