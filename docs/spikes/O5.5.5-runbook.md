# O5.5.5 speech preparation and listening review

Use the existing pinned Windows voice and Python environment. All output commands
require a fresh directory below `.local`; never put generated speech in Assets,
Git/LFS or public CI. The System.Speech file-output API is documented by
[Microsoft](https://learn.microsoft.com/en-us/dotnet/api/system.speech.synthesis.speechsynthesizer.setoutputtowavefile?view=netframework-4.8.1).
Synthesis writes WAV files and does not play them to the workstation speakers.

## Prepare

Obtain the stored #30 speech list for the exact study/set and its hash from the
verified #32/schedule chain. Do not regenerate or select a new balanced list.
Use DEMO materials for engineering checks; their flag cannot qualify a study.

```powershell
python tools/validity_speech.py plan --output .local/speech/run --speech-list $StoredSpeechList --speech-list-sha256 $ExpectedSpeechListHash
./tools/synthesize-validity-speech.ps1 -Requests .local/speech/run/requests.local.json -Output .local/speech/raw
python tools/validity_speech.py process --requests .local/speech/run/requests.local.json --raw .local/speech/raw --output .local/speech/bank
python tools/validity_speech.py validate --manifest .local/speech/bank/manifest.local.json
```

Expected output: 64 verified files, eight selected take-1 commands, status
`engineering_unreviewed`, exact measured durations and manifest SHA-256. Each
family must cover its four actions and four targets once. Retain raw WAVs and
the synthesis evidence with assembly/voice resource hashes. The CSV in the
private bank carries IDs, text, take, measured duration, file/PCM hashes and
chosen/spare status. No sentence is assumed to match a nonspeech cue's duration.

## Needs operator run

A second person must listen to all 64 files, including both identical synthesis
passes, checking the exact action and target, pronunciation, clarity, clipping
and the trim. Use a comfortable route and level. Do not fill review flags from
filenames, an automated transcript or the synthesis input. Record any failed file
and retain the failed bank; a replacement requires a new reviewed bank/hash.

Copy `listening-review.template.local.json` to a separate private review file.
Enter the coded reviewer, UTC time and each file's observed wording/clarity
result. Do not put identifying names in this file. Keep a real human sign-off
under the approved data plan; the software only validates its declared content.

```powershell
python tools/validity_speech.py freeze --manifest .local/speech/bank/manifest.local.json --review $CompletedListeningReview --output .local/speech/frozen
python tools/validity_speech.py validate --manifest .local/speech/frozen/manifest.local.json
```

The freeze refuses incomplete or negative reviews and binds their exact bytes
to the original bank. It creates new files, never overwrites the raw bank. A
DEMO bank remains DEMO even after a synthetic/engineering review and cannot
provide study PCM. No actual review was completed by this implementation task.

## Unity and final handoff

Run edit tests with `SPEECH_BANK_EVIDENCE` pointing to the unreviewed private
engineering bank and `AV_PACKAGE_DEMO_ROOT` to the verified producer DEMO artifact.
Without them, only those two explicitly named evidence tests may skip; ordinary
tests still must pass. Build commands use the existing Unity wrapper and short
private Gradle cache as in the #64 runbook. Keep fresh build IDs.

Provide #69 the reviewed manifest hash, independent review hash, exact stored
speech-list hash and its study/set scope. `LoadReviewed` verifies all files;
`ReadForValidity` additionally requires the stage's one-use authorization.
Before use, verify that scheduling speech before A D7/B W4 final protected blocks,
at B W1, or during ratings is rejected. Record actual speech durations in the
audio and trial events; no-cue slots have no audio request. These integrated
checks and the physical route/comfort checks remain pending.
