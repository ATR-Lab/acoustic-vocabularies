build IDs. The wrapper refuses overwriting evidence and marks dirty builds.

```powershell
$env:G1_DESCRIPTION_JSON = '<private-converted-g1-description.json>'

$env:PROTECTED_STATE_SOURCE_EVIDENCE = '<private-protected-source-evidence>'

./tools/build-unity.ps1 -Unity '<pinned-Unity.exe>' -Target Windows -Scene SelectionMenus -G1Description $env:G1_DESCRIPTION_JSON -ProtocolVersion '<protocol-version>' -BuildId menus-link-reviewed
```

`AV_PACKAGE_DEMO_ROOT` contains the existing producer's `package-demo` and
`dyad-demo` directories. The reserved assets are produced by #14. The codec
fixture is provisioned below. A test marked skipped because its private fixture
is absent is not a pass. Retain test XML, console output, source revision, build
manifests, native exit codes and independently recomputed artifact hashes.
Windows/Android compilation does not demonstrate headset operation.

## Actual Unity-to-Python store exchange

Start from a private DEMO bridge configuration satisfying
[`menu-store-bridge.schema.json`](../../apparatus/schemas/menu-store-bridge.schema.json).
Its bank file, canonical bank and package hashes must already be independently
verified. Provision only fresh output directories; the fixture tool reads that
bank/package and replaces the store path with a new store under its output. It
does not generate options or change the source store.

```powershell
$sourceConfig = '<private-DEMO-bridge-config.json>'
$sourcePin = (Get-FileHash -LiteralPath $sourceConfig -Algorithm SHA256).Hash.ToLowerInvariant()
& '<sound-Python>' tools/menu_store_fixture.py --config $sourceConfig --config-sha256 $sourcePin --out '<fresh-private-codec-directory>' --mode codec
& '<sound-Python>' tools/menu_store_fixture.py --config $sourceConfig --config-sha256 $sourcePin --out '<fresh-private-service-directory>' --mode service
```

The codec output supplies `AV_MENU_STORE_INTEROP`. It includes actual profile,
atom and verification requests/responses, initial/final snapshot pins and file
hashes. Do not hand-edit these into passing evidence.

Run the bounded service in one terminal:

```powershell
$fixture = '<fresh-private-service-directory>'
$config = Join-Path $fixture 'config.json'
$configPin = (Get-FileHash -LiteralPath $config -Algorithm SHA256).Hash.ToLowerInvariant()
& '<sound-Python>' tools/menu_store_bridge.py --config $config --config-sha256 $configPin --serve-mailbox (Join-Path $fixture 'mailbox') --seconds 300 --max-requests 4
```

Then run the Unity diagnostic in a second terminal, using that same private
service directory and a fresh log path:

```powershell
$env:AV_MENU_SERVICE_FIXTURE = '<fresh-private-service-directory>'
& '<pinned-Unity.exe>' -batchmode -nographics -projectPath '<checkout>/unity' -executeMethod AcousticVocab.SelectionMenus.Editor.MenuStoreInterop.Run -quit -logFile '<fresh-private-interop.log>'
```

Expected sequence: fresh empty-store verification, one P1 profile selection,
one rank-1 `K-a1` commit and a fresh verification. Expect four matching mailbox
responses, eight durable Unity intent/verification checkpoints, and
`MENU_STORE_INTEROP_PASS` only after the actual stored choice is handed back.
Inspect the created `unity-report.json` and compare its receipt hashes to the
Python journal and response files. The report must retain
`participant_ready:false`, `audio_played:false` and `timing_qualified:false`.
Measured request durations are software transaction observations, not audio or
network qualification. The service exits after four requests or its time bound.

If the editor never enters the diagnostic, preserve its startup log and record
the attempt as failed/incomplete. No requests is not a successful exchange. Use
a fresh fixture for the next attempt. If a store write became uncertain, retain
its intent/journal and follow the bridge's identical-request recovery procedure;
never delete records or silently substitute another candidate.

This transport requires co-located local files. An Android build does not make
the workstation mailbox reachable from Quest. A qualified deployment transport,
private permissions and trusted admission bootstrap remain prerequisites for
standalone operation. No network or runtime configuration change is authorized
by this diagnostic.

## Full menu and yoked checks

The generated scene contains the host and its dependencies but does not grant
study admission. Supply independently reviewed private scripts/meanings,
allocation, schedule, bank/package pins, measured audio route and fresh backend

one audio-owning module at a time and keep one engine tick owner. An uninstalled
host must not affect the next owner's player. Complete asynchronous control-mode
acknowledgment before explicit operator resume.

1. Use synthetic identities for engineering. Pair active and yoked runs for each
   visit before advancing the shared fixture store to the next wave; do not
   relabel a later store head as an earlier snapshot. Run the V1, V2 and V3 menu
   schedules in real elapsed time; retain every requested, onset-observed and
   completed play. Expected counts are 72, 32 and 32 plays respectively: eight
   profile plays plus 128 atom-menu plays across 17 menus. Fixed menu time sums to
   780 seconds, excluding admission leads and recorded inter-menu pauses.
2. Profile plays occur at 6.5, 10.5, 14.5, 18.5, 22.5, 26.5, 50 and 54 seconds.
   Atom plays occur at 5, 8, 11, 14, 17, 20, 35 and 38 seconds. Compare onset
   estimates and separately measured acoustic onsets to the recorded uncertainty;
   preserve requested, estimated, observed and measured quantities separately.
3. Revise the active choice within 30–45 seconds for profiles and 22–32 seconds
   for atoms. Test both valid choice and no-choice default. Changes at or after
   the deadline must be refused. The stored first option is the default, flagged;
   no additional audition or reserve option may appear.
4. Verify the store's exact before/after head, old entries and selected PCM/file
   hashes on every commit. Require the final complete-wave verification before
   teaching. Confirm 8, 12 and 16 accumulated entries across waves. A rejection
   or changed old hash must stop admission and preserve a deviation.
5. Seal only a complete active ledger. Within 24 hours, load it into the read-only
   yoked role using independent bank, asset, receipt and ledger pins. Choose an

6. Record both views. During yoked choice windows there must be no active cursor

7. In an isolated synthetic copy, test a wrong ledger pin, changed candidate
   byte, wrong receipt and changed old store entry. Each must block. Preserve
   original and altered test artifacts as distinct evidence.
8. Test a pause before the first cue, during a requested play and between menus.
   Keep partial audio events and matching-deviation IDs. An interrupted segment

   keep the yoked run paused with the matching deviation.
9. Inspect `MenuExposureProjection`: rejected candidates remain present; unknown
