# O6.1.2 view-capture leakage preparation

Status: offline verifier implemented; complete station capture and independent
review pending. No G3 acceptance, participant admission or qualified source
selection follows from this tool. The external methodology folder remains
unavailable, so these are explicit engineering proposals based on issue #79.

## Freeze before any capture

Copy `apparatus/spikes/O6.1.2/capture-plan.example.json` and the exact registered
neutral snapshot into a fresh operator-controlled private directory. Keep the
plan's snapshot reference relative to that directory. Replace the zero build and
panel hashes with independent pins for the actual binary and fixed response-panel
state. Confirm the actual source selected by the G2 decision; the example's live
setting does not make that decision. Provision the actual station identity.

The current profile requires exactly five distinct named views: center, yaw left,
yaw right, pitch up and pitch down. The example proposes one fixed Unity-world
camera position, yaw ±15 degrees and pitch ±10 degrees. These are **not** measured
headset poses or approved methodology constants. Establish the actual observer
reference and freeze all five absolute Unity left-handed, Y-up poses before the
run. Quaternions use XYZW. Isaac state retains its separate USD Z-up convention.
Do not change camera placement or tolerance after inspecting differences.

The current pixel tolerance is exactly zero on every decoded RGB/RGBA channel,
including alpha. Relaxing it requires a separately reviewed profile/code change.
The plan also fixes dimensions, a basic nonblank-color screen, maximum local
state-arrival age, and head matching bounds (at most 1 mm / 0.5 degrees). Head
poses must be distinct by more than the matching bounds. Registered-state bounds
cannot exceed #53: joints/orientation 0.5 degrees, positions 1 mm, velocities
1e-5 and workcell material/light scalars 1e-7. Discrete state, visibility, registry,
joint order, panel, text and routing remain exact. A dimension product over
4,194,304 pixels is refused to bound one 32-image pose group.

Independently record the plan's raw SHA-256 **before** capture. The verifier checks
the pin and declared capture ordering; it cannot prove predeclaration custody or
authenticate the operator. Use the already installed Python runtime:

```text
python tools/view_leakage.py --plan <absolute-private-plan.json> --plan-sha256 <raw-plan-pin> --validate-plan
```

## Capture contract — native integration still pending

There is no new automatic capture loop in this PR. The existing
`RenderedAcknowledgmentFramesMatchAllOutcomes` seam in
`unity/Assets/ExperimentApp/Tests/PlayMode/Assessment/AssessmentBlockTests.cs`
renders the real acknowledgment view for eight synthetic outcomes. It does not
load the full scene, issue all 32 commands or reproduce headset motion. Reusing
it requires a separately validated capture driver attached to the real protected
scene. Do not relabel its images as the required matrix.

The driver must run a nonstudy capture for every legal command and every pose
(32 × 5 = 160), with the response panel held constant and no scheduled study
audio. Load the trial through the real protected boundary, request a fresh reset,
observe its exact accepted test-mode acknowledgment, set/read back the fixed head
pose, then capture immediately before the real software cue request. All capture
timestamps below are decimal nanosecond strings from the **same client monotonic
clock**. Do not compare remote Isaac timestamps directly with them. Arrival age
does not qualify source-clock freshness or acoustic onset.

The private capture manifest has exactly these fields:

- `version: 1`, `scope: "actual_nonstudy_capture"`, `plan_sha256`, `station_id`,
  `clock_id` (32 lowercase hex), `plan_seen_ns`, `captures`, `command_log`.
- Each capture has `capture_id` (unique 32-hex), `pose_id`, `action`, `target`,
  `head_pose` (`position_m`, `rotation_xyzw`), `reset_received_ns`, `captured_ns`,
  `cue_requested_ns`, `state_sample_ns`, `reset_reply`, `image`, `state`, `audio`,
  `view`. The last five are `{ "path": "relative-name", "sha256": "raw-file-pin" }`.
- `reset_reply` is the exact native #55 private reply, with a fresh request ID,
  accepted successful reset or mode change, mode test, no fault/pause/demo and
  exposure-ready health. It is evidence to inspect, never a newly issued grant.
- `image` is the actual noninterlaced 8-bit RGB/RGBA PNG. Images and full state
  captures have distinct file paths per capture; an existing neutral file cannot
  be substituted for a missing sample. No resizing, normalization or image
  editing occurs. Palette, animation, interlace, malformed chunks, excess decoded
  bytes and changed CRCs are refused. Color interpretation metadata must match.
- `state` is the complete #53 readback shape: `robot`, `objects`, `environment`,
  `frames`. It must match the pinned snapshot's complete registries. Capture both
  the Isaac readback and the visibly applied state in the native driver; this
  verifier consumes the former, and their alignment still needs review.
- `audio` has exactly `spatial_blend`, `pan_stereo`, `doppler_level`, `spread`
  (all zero), `volume`, `pitch` (one), `mute` (false), `enabled` (true), `loop`
  (false), `output_mixer_group`, `route_id`, `source_count` (one), `effects` ([]).
  Read real settings; identical metadata cannot substitute for acoustic checks.
- `view` has exactly `panel_state_sha256`, `visible_text` (ordered strings),
  `renderer_inventory_sha256`, `console_visible` (false), `diagnostics_visible`
  (false). Inventory the actual visible renderers/text; declarations alone do not
  prove an overlay or hidden-answer object was omitted from capture.
- `command_log` references the actual #55 v0.3.1 private command JSONL. It must
  contain exactly one nonduplicate rejected demo request for every legal pair,
  with `PROTECTED_TARGET_COMMAND`, matching raw command/arguments/request ID,
  test mode, station and control session. The capture resets and lock probes must
  share that session. Preserve other raw evidence separately rather than editing
  a log to fit this diagnostic window.

Legal pairs are ADD_ONE, REMOVE_ONE, FLIP_CARD, ALIGN_ARROW × tray_A–D, and SCAN,
TAG, CLOSE, QUARANTINE × container_E–H. These are the existing public command API
names. Private capture records contain their intended pair; never publish those
records as participant output or use them as renderer input.

## Verify and investigate

```text
python tools/view_leakage.py --plan <absolute-private-plan.json> --plan-sha256 <raw-plan-pin> --captures <absolute-private-captures.json> --captures-sha256 <raw-manifest-pin> --output <fresh-absolute-private-report.json> --comparison-csv <fresh-absolute-private-comparisons.csv>
```

The output must be below a user private directory (`.local`, `private` or
`local-data`). Reads are bounded and pinned; linked/reparse/hardlinked, remote,
traversing or changed files are refused. No file is replaced. Exit 2 means
invalid/missing evidence; exit 1 means a complete comparison found differences;
exit 0 means this bounded offline screen passed. All results remain `HOLD`,
`g3_signed: false`, `participant_ready: false`.

The report and optional comparison CSV enumerate all 496 command pairs at each
of five poses (2,480 total). If a later export fails, retain the partial output
and retry with fresh paths; a partial export is not a successful run.
It checks each state against neutral **and** against every other command, avoiding
a two-sided tolerance error. It compares every decoded channel. A failure records
the first above-bound pixel, not an invented maximum or changed-pixel count.
Investigate every image, state, text, renderer inventory or routing difference;
retain the failed run and start a fresh pinned plan/run after any correction.

Archive the plan, independent pre-run pin, manifest, frames, state/settings files,
private command log, report and reviewer notes in restricted storage. A second
reviewer must audit hidden-tuple readers in the engine, state mirror, command
lock, demos, audio, logging and console. Review dynamic camera visibility, robot
asset appearance outside the registered workcell material/light accessor, and
the real capture boundary. No screenshot similarity substitutes for that review.
Optional response-closure capture must cover right/wrong/timeout with fixed
timing; the prior eight-acknowledgment result is only a separate bounded software
observation. Complete headset/live-or-selected-snapshot capture, natural head
movement, acoustic route confirmation and independent sign-off remain pending.
