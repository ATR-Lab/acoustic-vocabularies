## Private real-engine provisioning

Use `--config` instead of `--demo`. A private JSON file has `mailbox` (local shared
directory) and `visits` (alias-to-config mapping). Each visit supplies the fields
in `docs/interfaces/operator-console.md`. Paths refer to the reviewed private
#31 allocation list/reveal log, #32 manifest/CSV, #30 schedule/manifest and package
hash mapping. `manifest_sha256` must be independently verified; participant is
already bound by RevealLog. Never supply the restricted key. `anchors` carries
local calendar dates under D0/V1/V3 as applicable, and a UTC `active` timestamp
for yoked visits. No names/contact or scheduling records go in this catalog.

```powershell
python -m ops.console.server --config .local/console.local.json --audit .local/visit-audit.local.jsonl --protocol reviewed-version --port 8769
```

Configure the Unity adapter around the real #67 engine, durable journal, content
factory and trusted admission/health sources. Both sides pin the same loaded
visit. Absent/stale host stays unavailable. No native scene integration, LAN
endpoint or Quest deployment qualification is implied by unit tests.

The injected C# owner creates a fresh GUID32 nonce, opens
`FileOperatorCommandJournal(mailboxDirectory, nonce)`, then constructs
`OperatorMailbox(mailboxDirectory, nonce, reviewedRunSheetManifestHash,
validatedEngine, commandJournal, trustedAdmission, measuredHealth, monotonicMs)`.
Call only its `Tick()` on the owning thread; the engine pumps content before
deadlines. Dispose the mailbox before the journal on shutdown. Never synthesize
healthy device fields for a real visit. There is no participant MonoBehaviour or
scene wiring in this change. Preserve a failed publication temp file and command
audit; do not clear/replay an uncertain command or reuse a process nonce.

### Bounded actual-library interoperability probe

`tools/operator-mailbox-probe/` hosts the Unity-compiled engine/adapter DLLs in an
existing .NET runtime. Compile the Unity tests first, then build `Probe.csproj`
with explicit `UnityProject`, `NewtonsoftAssembly`, `ProbeOutput`, and private
`BaseIntermediateOutputPath`/`MSBuildProjectExtensionsPath` properties. These
references use existing approved libraries; the project adds no NuGet packages.
Run `run.py --probe-dll <built Probe.dll> --fresh-directory <new private folder>`.
It uses the actual Python Mailbox to load/start/pause/resume/stop the actual C#
engine, verifies one completed original at pause, five fsynced console receipts,
ten C# request/result audit rows, and stopped state. The two illustrative slots
use a virtual clock, synthetic readiness and no audio/participant scene. A failed
run retains stdout/stderr, state, audit and exception metadata. This proves the
control path only; it does not substitute for the paired hardware visit below.
