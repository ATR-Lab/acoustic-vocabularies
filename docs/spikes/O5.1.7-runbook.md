## Device checks before timing

This is a fixed world panel at 0.55 m from the reference origin, with 8 targets A–H, four actions filtered to tray family (A–D) or container family (E–H), Commit and an engineering-only Next control. `tray-1` etc. are placeholders pending private protocol verification. The reference eye height is 1.2 m, panel center 1.1 m. These are **proposed initial geometry**, not measured comfort values; record any changes and hold geometry constant across compared methods. The panel does not follow the head. Adjust only after measuring the fixed observer reference; verify reachable seated hand range without leaning.

Controller ray uses the configured hand's tracked controller pose and trigger rising edge. Hand poke uses XR Hands index-tip pose, a visible tip marker, and contact with button box colliders after withdrawal by at least 4 cm. Both use the same panel geometry. Hand support and actual ray aim/pose conventions still require device confirmation. If poses are misaligned, stop and correct transforms before collecting data.

Check no target/action is preselected, disabled Commit has no effect, changing A→B preserves its legal action, changing A→E clears it, and actions are disabled before a target. Deliberately try repeated trigger holds/pokes: one edge should produce one selection, not auto-repeat. Confirm a completed Commit requires Next before another prompt. All selection attempts, clears, disabled presses and Commits are logged on `Stopwatch` host time.

Test loss handling **before** comparison: power off/disconnect selected controller, obscure tracked hand/index pose, disable/re-enable hand subsystem where available, and remove app focus. Expected rows: `input_lost` with `controller_disconnected`, `controller_pose_lost`, `hand_subsystem_unavailable` or `hand_or_index_pose_lost`; focus emits `focus_lost`. An active attempt becomes paused, selections clear, prompts stop, and recovery does **not** automatically start a new exposure. After recovery, explicitly press Next to retry the same command with a new attempt number. Device polling occurs once per app frame, so measure detection/recovery delay and note outages the runtime does not report. Deliberate loss trials should be recorded separately from normal speed trials.

## Internal comparison

Use at least 3 internal team testers, who must not later serve as pilot or confirmatory participants. Seat each tester at the fixed reference. Give equal familiarization outside the recorded 32-command block. Switch hardware method as the prompt indicates (set controllers down for hand mode); Next starts the command prompt only when the selected method is tracked. Complete all 32 commands for both methods. Timing is **text prompt command to Commit** on a monotonic clock, not audible-onset response time. Prompt display frame latency is not measured by this spike.

Record wrong selections from events. Review headset capture with the tester after the block and annotate every Commit attempt's `accidental_commit` explicitly `true` or `false`; a wrong response is not automatically accidental. Use anonymous tester codes only. Record short comfort notes without identifying details. Keep captures private until metadata/privacy review. Capture each method with the headset's built-in capture or an already installed capture tool; no new tool installation is assumed.

Copy `annotations.example.csv` to `local-data/annotations.local.csv` and fill rows. Analyze all normal-run event files:

```powershell
python spikes/O5.1.7/input_analysis.py analyze --events local-data/t01-events.local.csv local-data/t02-events.local.csv local-data/t03-events.local.csv --annotations local-data/annotations.local.csv --output local-data/input-analysis
```

Outputs: `trials.csv` retains incomplete/loss attempts; `summary.json` gives median/p95 completed-attempt time, wrong selection count/rate (denominator = all target/action selection events), wrong Commits, reviewed accidental Commits, tracking-loss count and recovery durations. Unknown accidental counts remain `null`. Loss attempts are excluded from the speed distribution but counted and retained. Missing commands fail coverage; fewer than 3 testers × 32 commands per method cannot pass the 3.5 s screen. Do not pool legibility or deliberate-loss sessions with comparison sessions. Make any technical rerun's trial/session separation explicit; duplicate prompt/commit keys fail analysis.

## Legibility ladder

Use fixed eye reference and measure label distance/height. Set `text_angle_deg` in local settings (for example a descending 1.0°, 0.8°, 0.6°, 0.4°, 0.3° ladder; these are test settings, not results), restart, and ask each tester to read randomized target and action labels aloud without guessing. Record at least eight labels per angle per tester and include the longest actual labels privately once methodology is available. Keep the head at the reference; record fit/IPD and reach adjustments without personal identifiers. The runtime scales each rendered glyph bounding height using `height = 2 × distance × tan(angle/2)`, not the nominal font em-size. Verify actual glyph bounds in the headset and capture: renderer bounds/font changes can affect size, and the off-axis viewing geometry should be checked rather than assumed exact.

Fill `local-data/legibility.local.csv` from the header template and run:

```powershell
python spikes/O5.1.7/input_analysis.py legibility local-data/legibility.local.csv --tester-codes T01 T02 T03
```

Expected result is the smallest measured angle with zero errors for **every** named tester, multiplied by proposed 1.5× margin. Missing testers or errors leave the result incomplete. Recheck that candidate on the actual panel at all label positions and with actual protocol wording; ensure text fits button bounds. Record chosen size only after this check. The 1.5× margin and 3.5 s speed target are adopted proposals from #49, pending operator decision.

Fill results template, attach sanitized headset evidence, and publish reviewed derivative `docs/spikes/input/trials.csv` with tester codes only. ADR-004 requires method, measured text size and confirmed loss-event behavior. No choice is justified by the harness alone.
