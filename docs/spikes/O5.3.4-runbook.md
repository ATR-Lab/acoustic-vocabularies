# O5.3.4 state source verification

Use the pinned Unity editor and the approved built-in test packages. From the
repository, run:

```powershell
./tools/build-unity.ps1 -Unity <unity-executable> -Scene StateSources -G1Description <verified-g1-description> -Target Test -ProtocolVersion engineering-pending-review -BuildId state-edit-tests
./tools/build-unity.ps1 -Unity <unity-executable> -Scene StateSources -G1Description <verified-g1-description> -Target TestPlayMode -ProtocolVersion engineering-pending-review -BuildId state-play-tests
./tools/build-unity.ps1 -Unity <unity-executable> -Scene StateSources -G1Description <verified-g1-description> -Target Android -ProtocolVersion engineering-pending-review -BuildId state-quest
./tools/build-unity.ps1 -Unity <unity-executable> -Scene StateSources -G1Description <verified-g1-description> -Target Windows -ProtocolVersion engineering-pending-review -BuildId state-link
```

Use a new build ID each time. The wrapper discovers only project test assemblies
for the chosen platform and refuses an empty run. Participant builds use
`BuildOptions.None`; play-mode test assemblies are excluded from their source
audit through Unity's `PlayerWithoutTestAssemblies` API.

For the optional actual-recorded-contract test, privately set
`STATE_SOURCE_EVIDENCE` to a directory containing:

- `layout.json`: exact layout used for that run.
- `reset-check/neutral_v1.json`: actual captured, hash-verified #53 snapshot.
- `publisher-check/sample-first.json` and `sample-last.json`: retained real
  version 2 wire samples with the same station and scene identity.

The test loads all 43 joints and 60 objects through the C# parser. An unprotected
rate-run sample is not a neutral-parity measurement. Keep that limitation with
the result and do not substitute synthetic fixtures for actual recordings.

For a headset run, provision the #59 station config and the separate private
source config/neutral asset with measured hashes. Use the authorized isolated
station endpoint and approved clock evidence. Record a fresh 30-minute run with
`robot_state_source=live`, retaining sample-age CSV, events, build identity,
scene/layout/neutral/config hashes and every stale interval. Keep raw artifacts
private and publish only sanitized counts, percentiles and hashes.
The live URL ends in `/state`. While the app is stopped, provision
`state-source.local.json` and the named hash-verified neutral file beside
`station.local.json` in the app's persistent-data directory. On Quest this is
`/sdcard/Android/data/org.acousticvocab.experiment/files`; use the explicitly
selected device with `adb -s <device> push <private-file> <destination>`.
Use station values from approved apparatus records; the public placeholder
configuration is deliberately not runnable. Missing clock evidence permits
engineering preview but cannot pass the live cue-readiness gate.

At a safe boundary, request an independently logged backend reset. Confirm the
live source's rendered state and latest sample match the stored neutral before
enabling the next cue. Repeat with `robot_state_source=snapshot` using the same
app binary, then compare all joint/object states and matched neutral captures.
Changing source must require only station provisioning, not a rebuild.
The session controller must call `ConfirmReset()` at the safe boundary and
`CheckExposureReady()` immediately before scheduling the cue, alongside the
separate backend acknowledgment and its other fault gates. The scene host does
not play sounds or schedule trials. Source selection is read at startup; stop
and relaunch after changing the station config.

Deliberately test 200 ms, 300 ms and 2-second gaps with the harness first. On the
real headset, measure the actual injected interval and compare event duration
within one observed render frame. Do not infer real timing from a virtual test
clock. Corrupt a copied snapshot/trajectory byte and verify `HASH_MISMATCH`,
a logged fault and no cue readiness. Restore the verified artifact explicitly.

The #56 trajectory recorder supplies the eight orientation and 32 execution
files plus their private hash index. Do not fabricate those recordings or claim
teaching playback validation before actual Isaac captures exist.

## Meta XR Simulator functional checks

Use an already installed simulator with its Quest Pro profile and a Windows
StateSources build. Follow the [Meta simulator guide](https://developers.meta.com/vr/documentation/native/xrsim-getting-started-1.0/)
to select its OpenXR runtime. Record the previous active runtime before testing
and restore it afterward; the simulator frontend may change the system runtime
even when the player also receives a process-specific `XR_RUNTIME_JSON`.
Do not change station networking or install an update as part of this check.

Provision only synthetic station identity and the captured neutral/config hashes
in the private persistent-data directory. Preserve any preexisting configuration.
Launch the player with a fresh private log and retain its exact build identity.
Verify the workcell appears after the initial Device tracking origin settles.
Move focus away and back: the app must record the interruption, hide the scene,
and require explicit recovery. The simulator panel can display an older compositor
frame, so compare its view with the application window and durable event log.

With the app stopped, give a copied source config an incorrect neutral hash.
Relaunch and verify `HASH_MISMATCH`, no initialized source, and a hidden workcell.
Restore the verified configuration before the next run. Record simulated head
movement or tracking loss only if the runtime actually reports and renders it;
the headset-input toggle alone is not evidence of a tracking-loss event.

This exercise validates Windows runtime behavior. It cannot satisfy the physical
headset, acoustic-onset, tracking-loss timing, or 30-minute apparatus criteria.
Sanitized results and build/test hashes are in
[`state-sources-validation.json`](../unity/state-sources-validation.json).
