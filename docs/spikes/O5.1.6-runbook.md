## Capture and independently validate synchronization

Equipment required: loopback-capable USB interface, measurement microphone and ear-position coupler, wired earphones, and independent clock/trigger instrumentation for synchronization. Use acoustic capture on **every** route; capture electrical loopback on wired routes when accessible. Speakers' electrical loopback may be unavailable: mark it explicitly. Use one multichannel, signed 16-bit PCM WAV capture clock for acoustic/electrical/photodiode channels. Set safe recording levels without clipping; disable AGC, noise suppression, notifications and automatic volume changes; record all device settings. Fixed volume is not a sound-pressure calibration.

The full white camera flash marks each request visually. It is a **pairing diagnostic**: Unity's flash command timestamp precedes photon arrival by unmeasured render/display delay. Fitting flash-command timestamps directly to photodiode edges hides that delay and is invalid. The tool therefore refuses analysis without independent sync evidence.

Provide `sync-anchors.local.csv` with `host_s,capture_s,role`. Each anchor must refer to the **same independently timed physical event** in app monotonic and capture clocks. Establish this with calibrated hardware common-clock triggers/timestamps; if using the display, separately measure command-to-photon latency and its uncertainty with such instrumentation and correct the anchors. Document the instrument/procedure and measured worst uncertainty in `sync_calibration_evidence` and `sync_external_bound_ms`. No hardware timestamp adapter is claimed to exist in this repo; arrange it with the operator before asserting absolute offsets. A microphone/photodiode pair alone measures audio-to-photon delay and cannot supply the missing app-to-photon calibration.

Use at least 3 fitting and 3 **held-out** check anchors distributed before, throughout and after each run; label rows `fit` or `check`. Do not use audio onsets to create anchors. Mapping is affine to account for clock drift and refuses extrapolation outside anchors. Review check residuals for drift/outliers; the measured maximum check error plus instrumentation bound is added to onset p95 for conservative engineering screening. There is no assumed zero sync error.

Every timestamp and bound must be finite; anchor host times must be unique across
both roles. Express `sync_external_bound_ms` in host-clock milliseconds. The
analyzer converts held-out capture-clock residuals to host-clock milliseconds
before combining them with onset residuals and the external bound.

## Detect, pair and analyze

Copy settings template to `local-data/settings.local.json`, fill it with exported device settings, capture kind and independently measured sync details. Obtain detector threshold from a **separate** noise/control capture; freeze it for the run, keep it below pulse peaks but above noise, and report sensitivity across reasonable thresholds. Default criterion is 3 consecutive above-threshold samples with 100 ms refractory. Detector bias (pulse ramp, microphone/coupler response, threshold and channel skew) must be investigated using control pulses; do not tune per event.

```powershell
python spikes/O5.1.6/audio_onsets.py analyze --capture local-data/capture.local.wav --events local-data/events.local.csv --sync local-data/sync-anchors.local.csv --settings local-data/settings.local.json --channel 0 --threshold 0.02 --output local-data/audio-analysis
```

`0.02` is an example threshold, **not a calibrated setting**. Repeat for every acoustic/electrical channel with a distinct settings file and output directory. Expected outputs: `onsets.csv` with trial IDs, physical onset capture times and matching status; `summary.json` with mean offset, SD, p95/max absolute residual, independent sync errors, counts and 20 ms screening decision. Window `[request, request+0.8s]` is disjoint by construction. Missing pulses stay attached to their trial; multiple pulses are ambiguous; extra pulses are reported. Investigate every mismatch and capture interruption rather than silently deleting trials. The screen requires >=200 matched and zero mismatches/extras. A route passing the screen still requires review of synchronization coverage and repeat-session stability.

Analyze photodiode separately using the Python `read_pcm`/`detect` functions and the **independently fitted** mapping with `pair_events` against `flash_command_host_s`; document missing/ambiguous pulses and measured display lag. Never feed the flash result back as zero-error sync. Platform logs provide underrun evidence; missing acoustic pulses are not equivalent to underruns, and unknown counts remain unknown.
