Copy `bridge.example.json` to ignored `local-data/bridge.local.json`, fill URI/topology/rate/method and `canonical_joint_names`, and copy it into the app's persistent-data directory. Qualify a conservative relative clock drift bound from clock/instrument evidence for the run; fill `clock_drift_bound_ppm` and `clock_bound_evidence` with its measured bound and private evidence reference. The default `-1`/empty values deliberately prevent source-freshness claims or animation. A fitted mean or assumed perfect synchronization is not a valid bound. Without qualification, the benchmark records diagnostic warmup state and stops with `warmup_failed` after 30 s. Once a progressing, source-fresh frame is actually applied to the renderer, it writes `run_start` and measures the full requested duration; prior warmup rows remain explicitly labelled in the same file.

```powershell
adb push local-data/bridge.local.json /sdcard/Android/data/$packageId/files/bridge.local.json
```

Set `$packageId` from #45 locally. Build Android **IL2CPP** and Windows with the pinned build methods. A C# editor compilation is insufficient: verify each candidate actually connects on the Quest and animates the imported robot from live Isaac state. `ClientWebSocket` Android/IL2CPP support remains unverified until that device run. Retain a sanitized headset capture. Object coordinate conversion/rendering is not implemented by the joint adapter; fixed placeholder geometry must match the shared scene explicitly.

Socket receive time is captured on its worker before parsing. Main thread strictly validates fields/nested poses, canonical order, finite values, session tokens and source progression. It refuses replay, stalled sim state, source age with an upper bound above 250 ms, queued age above 250 ms, and missing clock qualification. `StateIsStale`, `TransportIsStale` and `AppliedStateIsStale` distinguish source, traffic and rendered-state health. Echo offset intervals allow asymmetric delay and expand with the qualified drift bound; intervals expire after 2 s. Gaps generate `stale_begin/end`; queue overflow invalidates a clean screen. A 2 s receive watchdog aborts an unresponsive socket; reconnect uses 0.25, 0.5, 1, 2, then 5 s capped backoff, resets old buffers/clock history and re-subscribes to rosbridge. This is spike fault detection, not the Phase 2 experiment-pause state machine.

Restart only the spike publisher/server and record exact intervention timestamps locally. Client logs detection-to-first-state reconnect duration; last pre-fault to first recovered receive gap is the complete observed outage. Detection delay differs from intervention-to-recovery time, so do not label them interchangeably. An outage at end-of-run is counted even if it never reconnects.

Compare resource samples to a no-bridge run with the same scene/render settings and duration. `publisher.csv` call cost is not total CPU: include JSON, transport/ROS threads and relay process cost, record relay separately using existing process monitoring. On Unity, `apply_ms` includes parse/validation/joint callback on main thread but not the rest of rendering or CSV I/O. Pair it with #45 frame timing/OVR metrics; do not claim it is total frame cost.
