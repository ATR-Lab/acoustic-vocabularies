## Build

Use Unity 6000.6.0f1 with Android SDK/NDK/OpenJDK support. Set `UNITY_EDITOR` in
your shell or ignored station configuration to that installed editor executable.
Set `ADB` to the installed Android SDK `platform-tools/adb` executable. Never put
absolute station paths, serials, account details or raw logs in the repository.
From repository root, close the project in the interactive editor, then run:

```powershell
./spikes/O5.1.3/invoke-unity.ps1 -EditorPath $env:UNITY_EDITOR -Action Configure
./spikes/O5.1.3/invoke-unity.ps1 -EditorPath $env:UNITY_EDITOR -Action Windows
./spikes/O5.1.3/invoke-unity.ps1 -EditorPath $env:UNITY_EDITOR -Action Android
```

Expected: exit success plus `OPENXR_SPIKE_CONFIGURED` or
`OPENXR_SPIKE_BUILD ... result=Succeeded errors=0` in ignored `.local/unity/`.
Outputs are `unity/spikes/openxr/Builds/Android/openxr-spike.apk` and
`unity/spikes/openxr/Builds/Windows/openxr-spike.exe`. A build failure is not an
operator result. Preserve its local log, fix the error and rebuild.

On the preparation station, Java's selector wakeup socket failed with `Unable to
establish loopback connection` in a redirected temporary directory. Use a short,
existing directory outside redirected AppData for the child process's TEMP/TMP.
Use a short Gradle cache directory as well: deeply nested managed-worktree caches
can exceed the bundled Ninja tool's 260-character filename limit. Store both
station-specific paths in ignored configuration and pass them only to this build:

```powershell
./spikes/O5.1.3/invoke-unity.ps1 -EditorPath $env:UNITY_EDITOR -Action Android -TemporaryDirectory $env:UNITY_SPIKE_TEMP -GradleCacheDirectory $env:UNITY_SPIKE_GRADLE_CACHE
```

These options only affect the child build process. They do not modify global
environment variables, Java installations, firewall rules or network settings.

## Standalone

Connect one Quest Pro by USB with developer mode and USB debugging authorized.
Inspect device state locally; do not copy serials into reports. `unauthorized`
requires accepting the headset prompt. No device was connected during preparation.

```powershell
& $env:ADB devices
& $env:ADB install -r unity/spikes/openxr/Builds/Android/openxr-spike.apk
& $env:ADB shell monkey -p org.acousticvocab.openxrspike -c android.intent.category.LAUNCHER 1
```

Expected: `Success` from install; the same seated workcell appears in the headset.
Seat and recenter the observer. Verify A–H positions, camera height, tracking and
world-space panel with the wearer. Do not count this setup period as measurement.
The app records under its persistent `files/openxr-spike/<random-run-id>/` folder.

First run with no requested rate to discover runtime rates in `events.csv`.
After a run, pull results to an ignored directory:

```powershell
New-Item -ItemType Directory -Force .local/results/openxr | Out-Null
& $env:ADB pull /sdcard/Android/data/org.acousticvocab.openxrspike/files/openxr-spike .local/results/openxr/standalone
```

Copy `apparatus/spikes/O5.1.3/spike-config.example.json` to an ignored
`spike-config.local.json`, set `requestedRefreshHz` to an actually offered rate,
then repeat for each offered rate. Retain `durationSeconds: 900`.

```powershell
& $env:ADB shell am force-stop org.acousticvocab.openxrspike
& $env:ADB push .local/spike-config.local.json /sdcard/Android/data/org.acousticvocab.openxrspike/files/spike-config.local.json
& $env:ADB shell monkey -p org.acousticvocab.openxrspike -c android.intent.category.LAUNCHER 1
```

Wait for `ready`, followed by 10 seconds warmup and at least 900 seconds of active
capture; `measurement_complete,true` closes files. The app leaves the scene visible.
Confirm `refresh_request_accepted,true` and that `current_refresh_hz` actually
matches the request. Rejected or unobservable rates are reported as unsupported or
unknown, never substituted silently. Restart for every condition.

Record compositor/frame timing with the already provisioned OVR Metrics Tool or
equivalent approved Meta runtime tool. If the tool is missing, request permission
to install it. Save raw output locally. Capture a short headset view separately:

```powershell
& $env:ADB shell screenrecord --time-limit 30 /sdcard/openxr-spike.mp4
& $env:ADB pull /sdcard/openxr-spike.mp4 .local/results/openxr/standalone-capture.local.mp4
```

Capture itself adds load: record whether it overlaps the timed run. If it does,
rerun the baseline without capture. A screen recording alone may not capture
compositor stalls; retain runtime metrics for actual presentation-freeze claims.

## Connection loss and onset of readiness

After baseline timing, start separate runs to remove the headset, allow sleep,
and disconnect Link. Annotate the operator action time and what was visible.
Copy `events-template.csv` locally and populate only callbacks actually observed.
The logger records app focus/pause, user-presence changes when exposed, XR display
running changes, input connection changes (characteristics only) and OpenXR session
state transitions. These callbacks are evidence, not a reliable one-to-one label
for headset removal, sleep or cable loss. Abrupt termination can lose up to five
seconds of buffered rows; retain logs and report incomplete runs.

The app's `ready` event requires a running XR display and tracked headset. Its
timestamp measures `BeforeSplashScreen` to ready. Separately measure process
launch-to-visible-ready with runtime tools/capture if required; do not label the
callback-based duration as whole app launch time. OpenXR states follow the
[OpenXR session state specification](https://registry.khronos.org/OpenXR/specs/1.1/html/xrspec.html#session-lifecycle).
