# O5.6.3 frame timing runbook

Keep participant data, raw captures, profiler recordings and station paths private.
The public setup is an engineering schema, not a frozen protocol/apparatus choice.
No runtime, package, firewall, display or headset settings are installed/changed
by these steps. Coordinate simulator/GPU work with other local tasks.

1. Verify the build, protocol, station, layout, observer and panel hashes. Read the
   runtime-offered refresh rates and choose an explicitly documented engineering
   rate in the station config. Do not claim that this choice passed the pilot.
2. Supply the matching private frame setup. `request` performs one in-app runtime
   request before the visit; `require_current` verifies an existing setting. A
   mismatch or unavailable report blocks readiness. Disable the stall hook for
   participant deployment.
3. The trusted owner installs `FrameCaptureHost` with the real Foundation, panel,
   data journal and fault callback. Wrap the actual content factory and compose
   the cue adapter into the existing audio sink after its durable request write.
   The PCM-duration resolver must use the verified wave and match its PCM hash.
   Keep each attempt's registered windows through its full end.
4. Run the heaviest full scene on the chosen topology: live G1 mirroring, response
   panel, and lesson highlights. Capture render intervals throughout every cue and
   response window of a complete synthetic 36-trial block. Keep render callback,
   runtime report, physics, and independent headset presentation measurements
   distinct. Preserve profiler captures and raw before/after evidence if optimizing.
5. In a synthetic response window only, opt into the bounded engineering hook and
   inject 200 ms then 300 ms in separate runs. Check observed duration rather than
   assuming `Thread.Sleep` equals its request. Exactly 250 ms is not a freeze;
   >250 ms is. Verify the watchdog fault time, next main-thread dispatch, the
   durable trial maximum and the console fault. Repeat with panel availability
   lost while frames continue: in the `FrameProbe` simulator build use
   `-frameProbeStall 0 -frameProbePanelLoss` (separate run, fresh output
   directory) and check for exactly one `FRAME_INTERFACE_UNAVAILABLE` fault at
   `injected_mono_ms` with no `FRAME_FREEZE`. Never inject stalls or panel loss
   into a participant visit.
6. Inspect captured baseline/cue bindings, window intersections, row counts, final
   summaries and manifest hashes. A missing/incomplete segment cannot establish
   zero freezes. The 99% within 1.5× nominal criterion remains proposed until
   accepted, and simulator or virtual-clock traces cannot qualify a headset.
7. Recruit three eligible lab volunteers outside study cohorts through the human
   protocol process. Use only approved non-study placeholder audio. At the fixed
   seated observer pose, record each of A–H and all eight action labels, coded
   volunteer ID, contrast/size, discomfort and any remediation. Keep names and
   contact information outside these records. No such observations are generated
   by software tests.
8. After physical review, freeze the verified size, contrast, layout/observer
   hashes and `display_resolution_refresh` fields for #83. Until then leave the
   apparatus template unqualified with missing values null.

Commands for the existing Unity editor are in `tools/build-unity.ps1`. Supply the
reviewed existing G1 description and private package/evidence fixtures for tests.
Use fresh build/capture IDs so earlier failures remain available. Native Android
compilation is not Quest runtime or thermal qualification; no headset currently
means those operator steps stay pending.
