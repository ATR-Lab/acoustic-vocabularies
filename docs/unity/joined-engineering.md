# Staged engineering bootstrap

`JoinedEngineeringBuild` builds a seated G1/workcell scene with one shared audio player, frame capture, response panel and `JoinedEngineeringBootstrap`. It loads an explicitly pinned private configuration using `-joinedConfig <path> -joinedConfigSha256 <raw SHA256>`. There is no automatic study start, allocation, orientation, runtime switch, bridge launch or calibration generation. `ParticipantAdmission` is always false. Missing configuration or authority is a bounded `JOINED_ENGINEERING_STATUS` message in the private player log; it is not a participant debug overlay.

Use [the preparation tool](joined-engineering-preparation.md) to copy explicit existing inputs into a fresh private directory. Provision its listed station, state-source, neutral and response-panel files separately using the existing station procedure, preserving previous files. The bootstrap verifies both current file bytes and the configurations actually loaded by the running components. All configuration paths are confined to the private root; optional absent authorities are explicit nulls.

The package and schedule must both be DEMO artifacts. Their actual producer IDs remain unchanged: configuration `unit_id` must equal permutation `unit_id`, and `coded_id` must equal schedule `person_id`. The visit, station, protocol and build must match. For the existing synthetic menu-store namespace only, bridge unit ID is deterministically `DEMO-` plus the producer unit, for example `B-C01` → `DEMO-B-C01`. Both identities are recorded. An arbitrary earlier codec-interoperability fixture is not a joined-visit authorization. Shared active/yoked ledger identity hashes package, raw permutation, bank and producer unit, excluding participant session/build/local paths.

The block map is derived from the exact validated producer trial types. Profile and atom menus use the menu host; atomic and message lessons use teaching; pre-old, trained, atomic, novel, no-cue and speech slots use assessment. Mixed or unknown blocks fail closed. Study B profile/ranks come only from the same visit-owned `FileMenuStore`, including all verified previous selections. Assessment-only W1/W4 visits open the complete 16-entry store read-only. There is no default rank or reserve-rank substitution.

At a safe boundary, after the entire retained visual tail, the coordinator disposes the previous view/factory/control lease. It stages a fresh real control client, mode acknowledgment, neutral reset acknowledgment and independent renderer confirmation. It pumps this handshake without advancing the engine. The prepared assessment instruction remains visible until an explicit operator command. The operator mailbox alone calls `engine.Tick`; start/resume consumes a prepared lease once before `ConfirmResume`. An unplayed pause and a normal same-block pause both require a fresh backend lease. Stop discards pending preparation. Partial construction and disposal failures latch the joined owner; every registered cleanup is attempted.

One menu ledger spans profile and atom blocks and module leases. The final menu's existing `RequestVerification(true)` and reset gate must finish. Before a later non-menu control mode is started, the full menu ledger is sealed against actual candidates, meaning IDs and immutable store receipts. Pre-old blocks that precede menus are not subject to that later seal. Partial or interrupted menu evidence remains unsealed and cannot be silently replayed or reconstructed.

Session, panel, every actual audio request/observation, assessment-stage and frame events use the shared data journal/adapters. Verified-wave bindings are registered before scheduling. Lesson, control and store events have supplemental private append-only chained evidence; menus use their strict ledger. Output callback coverage is not acoustic delivery evidence. The assessment journal survives module switches. No raw records enter the web console. External qualification headers and approved encrypted upload storage remain separate requirements.

After protected trials, the current assessment lease presents reviewed forms and retains its control pump until durable forms completion. A pending reconstructed view also keeps its handshake alive while forms are shown. Normal engine completion is reported as joined completion only after forms. If a completed engine is recovered without an installed forms view and without durable completed forms, startup reports `JOIN_FORMS_RECOVERY_REQUIRED`; reconstructing that forms-only native view remains unfinished software. DEMO speech validity is explicitly refused as `JOIN_DEMO_VALIDITY_UNSUPPORTED`, preserving the existing non-DEMO speech qualification rule. Optional post-W4 execution remains qualification-blocked.

Other unfinished joining work is distinct from physical qualification: yoked startup still requires independently pinned active schedule and sealed ledger plus an explicitly authorized, one-use **current-process** future monotonic anchor, shared across its menu leases. The bootstrap reports `JOIN_YOKED_REPLAY_ANCHOR_REQUIRED`; it never invents an anchor from the current time or an old process timestamp. Silent orientation/grammar entry and participant allocation are separate qualified entry flows, not bypassed or declared completed here.

Both Windows and Android targets use the installed pinned Unity dependencies. Run `tools/build-unity.ps1 -Scene JoinedEngineering` with the reviewed local G1 description and a fresh build ID. Native build/startup evidence is recorded separately from software lifecycle tests and from a complete visit. Missing route measurements, comfortable-gain history, reviewed wording/images, final bank handoff, headset checks and protocol approval cannot be supplied by this engineering switch. Meta XR Simulator remains the selected system runtime at the user's instruction; a run marked `runtime_settings_changed:false` made no additional runtime change.
