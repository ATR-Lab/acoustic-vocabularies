# Staged engineering bootstrap

`JoinedEngineeringBuild` builds a seated G1/workcell scene with one shared audio player, frame capture, response panel and `JoinedEngineeringBootstrap`. It loads an explicitly pinned private configuration using `-joinedConfig <path> -joinedConfigSha256 <raw SHA256>`. There is no automatic study start, allocation, orientation, runtime switch, bridge launch or calibration generation. `ParticipantAdmission` is always false. Missing configuration or authority is a bounded `JOINED_ENGINEERING_STATUS` message in the private player log; it is not a participant debug overlay.

Use [the preparation tool](joined-engineering-preparation.md) to copy explicit existing inputs into a fresh private directory. Provision its listed station, state-source, neutral and response-panel files separately using the existing station procedure, preserving previous files. The bootstrap verifies both current file bytes and the configurations actually loaded by the running components. All configuration paths are confined to the private root; optional absent authorities are explicit nulls.

The package and schedule must both be DEMO artifacts. Their actual producer IDs remain unchanged: configuration `unit_id` must equal permutation `unit_id`, and `coded_id` must equal schedule `person_id`. The visit, station, protocol and build must match. For the existing synthetic menu-store namespace only, bridge unit ID is deterministically `DEMO-` plus the producer unit, for example `B-C01` → `DEMO-B-C01`. Both identities are recorded. An arbitrary earlier codec-interoperability fixture is not a joined-visit authorization. Shared active/yoked ledger identity hashes package, raw permutation, bank and producer unit, excluding participant session/build/local paths.

The block map is derived from the exact validated producer trial types. Profile and atom menus use the menu host; atomic and message lessons use teaching; pre-old, trained, atomic, novel, no-cue and speech slots use assessment. Mixed or unknown blocks fail closed. Study B profile/ranks come only from the same visit-owned `FileMenuStore`, including all verified previous selections. Assessment-only W1/W4 visits open the complete 16-entry store read-only. There is no default rank or reserve-rank substitution.

At a safe boundary, after the entire retained visual tail, the coordinator disposes the previous view/factory/control lease. It stages a fresh real control client, mode acknowledgment, neutral reset acknowledgment and independent renderer confirmation. It pumps this handshake without advancing the engine. The prepared assessment instruction remains visible until an explicit operator command. The operator mailbox alone calls `engine.Tick`; start/resume consumes a prepared lease once before `ConfirmResume`. An unplayed pause and a normal same-block pause both require a fresh backend lease. Stop discards pending preparation. Partial construction and disposal failures latch the joined owner; every registered cleanup is attempted.

One menu ledger spans profile and atom blocks and module leases. The final menu's existing `RequestVerification(true)` and reset gate must finish. Before a later non-menu control mode is started, the full menu ledger is sealed against actual candidates, meaning IDs and immutable store receipts. Pre-old blocks that precede menus are not subject to that later seal. Partial or interrupted menu evidence remains unsealed and cannot be silently replayed or reconstructed.

Session, panel, every actual audio request/observation, assessment-stage and frame events use the shared data journal/adapters. Verified-wave bindings are registered before scheduling. Lesson, control and store events have supplemental private append-only chained evidence; menus use their strict ledger. Output callback coverage is not acoustic delivery evidence. The assessment journal survives module switches. No raw records enter the web console. External qualification headers and approved encrypted upload storage remain separate requirements.

After protected trials, the current assessment lease presents reviewed forms and retains its control pump until durable forms completion. A pending reconstructed view also keeps its handshake alive while forms are shown. Normal engine completion is reported as joined completion only after forms. A completed-engine restart reconstructs the strict ordered stage history and presents only remaining forms through `CompletedFormsRecovery`, without audio, backend modes, content factories or additional engine ticks. It reports `JOIN_FORMS_RECOVERY_ACTIVE` until completion. DEMO speech validity is explicitly refused as `JOIN_DEMO_VALIDITY_UNSUPPORTED`, preserving the existing non-DEMO speech qualification rule. Optional post-W4 execution remains qualification-blocked.

Yoked startup uses configuration v2: independently pinned active run-sheet/schedule files and a sealed active ledger, plus an explicit `operator_start_plus_lead` policy (2–60 seconds). Only the already-durable, nonce/hash-bound Start/Resume command can consume a fresh current-process anchor. That anchor and clock epoch are fsynced before replay loading. The expected active binding is derived from the validated paired schedule/allocation, never its ledger header. One replay object spans profile and atom leases, and `SealYoked` checks exact recorded events after final store verification. Missed anchors and interrupted segments do not silently reanchor or replay.

[The separate preallocation entry](preallocation-entry.md) keeps the joined loader disabled throughout silent orientation and operator allocation. It verifies a finalized orientation receipt and the durable operator eligibility/reveal chain before opening joined configuration or package bytes. It remains engineering-only. The reserved-example grammar entry is joined at the first teaching boundary as described below; its software completion never asserts acoustic or participant qualification.

## Reserved grammar boundary

Configuration v3 adds the independently pinned optional `grammar_review` file (maximum 1 MiB). Versions 1 and 2 retain their exact closed shapes; a visit containing teaching cannot start without the new review, `reserved_registry`, and the verified `grammar` directory. The review must have exactly these fields: `version:1`, `approved:true`, the actual `methodology_sha256` matching the teaching review, `registry_sha256`, `boundary:"before_first_teaching_block"`, `repeat_policy:"once_per_visit_no_partial_replay"`, `scheduling_lead_ms:750`, `completion_authority:"software_delivery_only"`, and `labels:{ready:"READY",action:"Action",target:"Target"}`. This is a required external review record, not a template that the program approves. No such reviewed authority or route measurement was created by engineering tests.

At the first teaching boundary, after the preceding visual tail and fresh neutral/control handshake, the first explicit Start/Resume is durably consumed to begin the existing reserved-only sequence. The engine stays awaiting operator confirmation and requests no study cue. READY is presented with the verified ready cue, then Action/Target roles with the verified click demonstration, using the existing 750 ms scheduling lead after software completion. While it runs, further starts are refused by readiness. The next explicit Start/Resume can advance teaching only after both requests, actual output callback completions, and the final grammar marker have been durably recorded. There is no automatic resume.

`grammar_stage` rows share the fsynced hash-chained `DataJournal`, use a separate clock epoch and contain no opportunity/attempt IDs. They retain the operator command identity and each actual audio observation with PCM/file hashes. They remain in raw exports and do not enter trial/exposure CSVs or confer acoustic truth. A finished ordered sequence is restored after restart. Any partial, uncertain, interrupted or unmatched history blocks replay; prior consumed teaching without a finished grammar history is an explicit migration refusal. Pause/Stop during familiarization preserves the consumed stage and latches the owner. The reserved host relinquishes the shared player before the teaching factory subscribes. Raw frame callbacks continue; these reserved plays are not mislabeled as trial response windows.

Optional native soak capture uses `-soakPlan <path> -soakPlanSha256 <raw pin> -soakOutput <fresh directory>`. The plan must bind the actual station/build/scene/neutral/schedule and explicitly describe a nonparticipant live-source capture. It records actual visible live application and `onBeforeRender`, with a separate Stopwatch watchdog. A missing joined authority produces paused context; it cannot become teaching/protected evidence. No source, mode, settings or readiness is changed by capture.

Both Windows and Android targets use the installed pinned Unity dependencies. Run `tools/build-unity.ps1 -Scene JoinedEngineering` with the reviewed local G1 description and a fresh build ID. Native build/startup evidence is recorded separately from software lifecycle tests and from a complete visit. Missing route measurements, comfortable-gain history, reviewed wording/images, final bank handoff, headset checks and protocol approval cannot be supplied by this engineering switch. Meta XR Simulator remains the selected system runtime at the user's instruction; a run marked `runtime_settings_changed:false` made no additional runtime change.

[Validation and exact manifests](joined-engineering-validation.json) record clean JoinedEngineering and PreallocationEngineering Windows and Android ARM64 IL2CPP builds at `7965eb8`. The final broad EditMode run passed 697 cases with no failures and one explicit Windows symlink-privilege skip; all 21 headless PlayMode cases passed. Independent verification covered all 480 command-integrity exports. The earlier checkpoint and separate repair/retest runs remain identified in the evidence record.

The final joined Windows player was launched with a sealed DEMO package, recorded G1 snapshot and absent optional authorities. It logged `JOIN_AUDIO_CALIBRATION_MISSING` before owner creation, then the explicitly requested bounded diagnostic quit completed with exit 0. All four temporary station files were restored to their original absence, without a forced stop or runtime setting change. The earlier forced-stop observation remains historical evidence, superseded only by the actual new clean-exit runs. This verifies startup refusal and shutdown, not a full visit or physical/acoustic qualification.
