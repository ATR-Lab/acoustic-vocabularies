# DEMO allocation lists (synthetic)

These files were generated by

```sh
uv run --project schedules python -m av_schedules allocate \
    --pilot-demo-seed DEMO-o4.4.3-pilot --confirmatory-demo-seed DEMO-o4.4.1-example \
    --out schedules/examples/demo-allocation
```

from public seeds. They are format and balance examples only: they are not study
material and must never be used with participants. Every JSON file carries
`"demo": true`. The confirmatory seed is the curriculum example seed, so the
confirmatory lists are built from the batch and design tables in
[`../demo/`](../demo/README.md) (`design_table_sha256` matches them). The pilot lists use
their own seed, because pilot and confirmatory lists never share a master seed.

Contents, per study:

- `A/<set>-slots.json`: learner-facing slot list (slot -> anonymous book ID), no method labels.
- `A/<set>-book-key.json`: restricted key (book ID -> batch, method, A1 designer).
- `B/<set>-dyads.json`: concealed dyad list (roles by member slot, bank, menu order).
- `<set>-assign-balance.csv`: balance report.
- `<set>-assign-manifest.json`: seed fingerprint, generator version, list and file SHA-256.

`tests/schedules/test_allocation.py` regenerates the examples and fails if any byte
differs. Real lists are generated from private seeds into restricted storage; only their
hashes are published.
