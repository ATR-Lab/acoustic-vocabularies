# DEMO run sheets (synthetic)

These files were generated by `python -m av_schedules run-sheet-examples` from the public
pilot seed `DEMO-o4.4.3-pilot` (the seed of the pilot lists in
[`../demo-allocation/`](../demo-allocation/README.md), so the Study A book IDs match
`A/pilot-slots.json` there). They are format examples only: they are not study material
and must never be used with participants.

Contents, per study:

- One run sheet per visit of one person: `A/A-P01/run-sheets/A-P01-L01/{D0,D7}.csv`
  and both members of one dyad slot, `B/B-P01/run-sheets/B-P01-M{1,2}/{V1,V2,V3,W1,W4}.csv`.
  The header is exactly the methodology visit run-sheet template; one row per schedule
  block. `participant_id` holds the synthetic person slot ID.
- `pilot-package-hashes.json`: a DEMO **placeholder** package-hash mapping
  (`"placeholder": true`): no package exists for these values. The run sheets therefore
  show `DEMO-placeholder:<hex>` in `hash_check`; real mappings give `sha256:<hex>`.
- `pilot-run-sheets-manifest.json`: template hash, the SHA-256 of the pilot schedules
  manifest the sheets were built from, bookings and the SHA-256 of every pilot run sheet
  (36 for Study A, 80 for Study B; the others are not committed here).

The run sheets were written only after the schedule validation suite (`av_schedules.checks`)
reported no finding for the whole pilot set. `tests/schedules/test_run_sheets.py`
regenerates the examples and fails if any byte differs. Real run sheets are generated
from a private master seed into restricted storage; only manifest hashes are published.
